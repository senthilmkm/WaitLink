Community Carpool & Seat Sharing

JumpIn — Share a Ride, Fill Empty Seats, Stay Connected by Text

JumpIn is a free, zero-app-install community carpool tool built into WaitLink. Drivers post an upcoming trip in seconds, riders reserve one or more seats for themselves or their family, and everyone coordinates via private SMS magic links — no logins, no passwords, and no payment processing.

No App or Account Needed Works in any iOS or Android mobile browser with one-tap SMS manage links.
Privacy-First Design Phone numbers stay hidden on public ride boards; riders only see names and trip updates.
Family-Friendly & Real-Time Book 1–6 seats in one reservation, adjust seat counts, and message in real time.
Community Supported Free to use with optional Zelle/Venmo tip cards to help cover SMS delivery costs.
🚗

1. Definition & Description of JumpIn

JumpIn connects trusted community members heading in the same direction. Instead of messy group chat threads where seats get double-booked or ride details get buried, JumpIn gives every trip a single live page with real-time seat tracking and automated text alerts.

How It Works

A driver posts a route (From → To), departure time, estimated trip duration, available seats (1–6), and an optional pickup note. JumpIn generates a shareable ride link and texts the driver a private management link.

How Riders Join

Riders open the shared link or browse the live JumpIn board, enter their name, phone number, and number of seats needed (e.g., 3 seats for a family), and instantly receive a private SMS link to manage their reservation.

How Access & Safety Work

Each device holds a cryptographic secret in local storage (or via SMS recovery link). Admins can enable Members-Only access, require Ride Approval, block abusive numbers, and cap daily SMS usage.

3. Lifecycle of a Trip

Every JumpIn trip follows a predictable, race-condition-free state machine from creation to cleanup.

Stage 1 (Optional)

Pending Approval

If Admin sets New rides wait for approval = Yes, the trip is hidden until approved (or declined) by an admin.

Stage 2

Open (Pre-Departure)

Listed on the live JumpIn board. Riders can reserve or update seats, cancel seats, and message. Driver can cancel or add passengers.

Stage 3

In Progress (Departed)

Once now ≥ departAt, new seat bookings/cancellations lock. Messaging stays open, and the driver sees Complete trip.

Stage 4

Completed / Cancelled

Triggered manually by Driver (or auto-completed at depart + duration + 60m). Compose box hides; Zelle support card & optional thank-you SMS fire once.

Stage 5

Retention & Purge

Private reservation/phone data is deleted 7 days after completion/cancellation; public trip stub is deleted after 30 days.

Idempotency & Race-Condition Protection: All seat reservations, seat updates, cancellations, and trip completions execute inside atomic Firestore transactions. Even if two riders tap Confirm seat at the exact same millisecond for the last seat, only one succeeds — and post-ride thank-you SMS is locked by thankYouSentAt so it is never sent twice.

4. Driver Workflow (Stage-by-Stage Operations)

Everything a driver can do from posting a ride to completing it — including switching to another phone mid-trip.

Trip Stage Operations Driver Can Perform System & SMS Behavior
Posting a Ride
  • Enter name, phone (auto-remembered after first use), From, To, date/time (or 1-tap Today / Tomorrow / In 30m / 1h / 2h presets), seats (1–6), Estimated duration (30m–15h via 30m stepper), optional Ride cost per seat ($), and optional note.
  • Tap Post ride (spinner shown while saving).
  • On Trip posted screen: tap 📋 Copy next to URL or the primary Share on WhatsApp button.
 SMS Sent Texts driver the private manage link (view=trip). Checks daily post cap, blocklist, and Members-Only whitelist.
Pending Approval
(if enabled)
  • View waiting status on manage link.
  • Edit trip (update departure date/time, total seats, or pickup note before departure).
  • Cancel trip (opens confirmation modal).
  • Sign out on this device.
 Ride stays hidden from public board until Admin approves. Messaging and adding passengers are disabled while pending.
Open (Before Departure)
now < departAt
  • Confirm joined riders (Tap to confirm → ✓ Confirmed): Each newly joined rider shows an amber Tap to confirm pill; tap it to mark them ✓ Confirmed (updates the rider's view to ✓ Confirmed via carpoolAckRider).
  • 2-Button Bottom Sheets: Tap Manage trip (Edit trip, Post return trip, Complete trip, Cancel trip) or Manage passengers (Add passenger, Adjust / Remove seats with − / + stepper).
  • Message passengers using 1-tap quick pills (On my way, At pickup spot, 5 min late) or custom text + inline Send (with spinner); past messages live in collapsible 💬 Trip Updates.
  • Add passenger manually (1-tap seat pills if seats left > 0; driver-added passengers start as ✓), or tap ✕ next to a passenger before departure to Remove them or reduce their seat count (confirmation modal with − / + stepper) and free seats.
  • Post return trip (1-tap pre-filled reverse route) or Cancel trip (confirmation modal: Keep trip / Cancel trip).
  • Share on WhatsApp / Copy link or Sign out on this device.
 SMS Sent Driver messages text all active riders. Adding a passenger texts that passenger their seat link. Cancelling notifies all active riders.
In Progress (Departed)
now ≥ departAt
  • Message passengers (shown when 1+ passengers joined) using quick pills or custom text + inline Send.
  • Complete trip (shown when 1+ passengers joined) — opens centered Complete this trip? confirmation modal with spinner.
  • Cancel trip remains available at any time before completion.
  • Add passenger is hidden once departed.
 SMS Sent Completing the trip marks it completed and sends the optional thank-you + Zelle tip SMS to driver & active riders. If 0 passengers joined and the driver forgets, the scheduler auto-cancels the trip with 0 tip SMS.
Completed / Cancelled
  • View final trip summary, passenger list, and trip updates.
  • Copy community Zelle/Venmo handle from the warm gold Support Card.
 Message box and action buttons are cleanly hidden. If driver didn't tap Complete, the 5-minute scheduler auto-completes after depart + duration + 60m.
Requesting a Ride
Need a Ride enabled
  • Tap Post a ride → choose Step 1 · 🙋 I need a ride (neither option is pre-selected so every post is intentional).
  • Enter route, date/time, Seats needed (1–6, up to group max), optional Willing to chip in ($ / seat), and optional pickup note.
  • Confirmation screen & request details include a shareable link with inline 📋 copy icon, Share on WhatsApp, ✕ Cancel request, and Sign out on this device.
  • Once a driver taps 🚗 I can drive, your seats are automatically ✓ Confirmed, and you can message the driver, update seats, or cancel your seat.
 SMS Sent Texts requester their manage link (respects New rides wait for approval if enabled). When a driver claims the request, texts both the requester (view=ride) and driver (view=trip).
Recurring Weekly Rides
  • In Post a ride → I'm driving, switch Repeat from One-time to Weekly.
  • Pick weekdays (S–S), duration (2 / 4 / 6 wks, capped by group horizon), and tap any preview date chip to skip holidays or days off.
  • Each day creates an independent trip (marked 🔁 Weekly) so riders book per day; drivers can also cancel all upcoming rides in the series from Manage trip.
 1 SMS Total Sends a single summary SMS to the driver for the entire series instead of N separate texts.
Car Info & Trip Count
  • Drivers can add optional Car / Color (e.g. Silver Honda CR-V) in + Add car, price, or note (remembered on the device).
  • Verified ✓ N trips badges appear automatically after completing rides with active riders.
 Helps riders spot the right car at pickup and builds community trust automatically.
Another Phone / Recovery
  • Open ride link → tap Driver? Manage this trip.
  • Enter driver phone → tap Text me a link.
 SMS Sent Works both before departure and mid-trip (until depart + duration + 60m). Always displays a neutral confirmation message to protect privacy.

6. Admin Workflow (Community Governance & Controls)

Authenticated via Google Sign-In on jumpin-admin.html. Responsive desktop table and mobile app layout (bottom tab bar, bottom-sheet modals, and 📲 Add to Home Screen PWA support for iOS & Android), with spinner feedback and confirmation modals on destructive actions.

Admin Tab Operations Admin Can Perform Notes & Safeguards
Trips
  • Filter by Upcoming, Pending Approval, Past, or Cancelled, and search by route/driver/last-4 digits.
  • Approve, Decline, or Block drivers on pending trips.
  • Open Details modal to inspect riders and trip messages.
  • Text trip to message a specific ride, or Cancel any active trip.
  • 📣 Broadcast SMS (top-right of Trips card, when enabled in Feature Config) sends an announcement SMS to upcoming trips or all saved contacts.
 All phone numbers are masked to last 4 digits. Broadcasts show a recipient count & daily SMS budget preview before confirming.
Members
  • Use + Add Member or Bulk Import in the card header (with inline validation) to add US/Canada members.
  • List-first, alphabetically sorted 2-column grid on desktop (1-column on mobile), 12-per-page pagination, and instant search by name or last 4.
  • All Members / 🛡️ Group Admins / 🚫 Blocked filter pills next to search (manage blocked people & unblock directly in one place).
  • Click Edit on a member to update Name, Phone, optional Email, Group admin checkbox, or Block / Unblock & Remove (with confirmation modals).
 Used when Members only = Yes. Non-members receive a red contact message directing them to the Admin contact email.
Settings
  • Toggle JumpIn is open (Soft Pause when set to No: blocks new posts, requests, claims, and reservations while allowing existing trips to finish), New rides wait for approval, Members only, and Post-ride thank-you text.
  • Configure Admin contact email, Admin sign-in emails, and Support / Tip handle (e.g., Zelle:name@email.com).
  • Tune safety limits: Daily text cap, Seats per trip (1–6), Days ahead, Messages per trip, Daily posts per phone, Upcoming seats per phone, Manage texts per record, and Resend cooldown seconds.
 Validated and clamped server-side on every save. All cloud functions preserve every config field atomically so settings never get overwritten.
Cleanup
  • Run two-step verified data purges for: Past trips, All trips, Saved contacts, or Everything.
 First checks exact item counts, then requires explicit confirmation in a modal before deleting records.
My Groups
Header & ?tab=groups
  • Organizers: Sign in with Google on jumpin-admin.html?tab=groups (or click My Groups in the console header), click + New Group, enter group name, slug (?g=<slug>), and required US/Canada phone, then click Copy Link / Copy Board Link once approved.
  • Platform Admin: Approve, Suspend, Resume, reject, or delete non-default groups (with clear confirmation popups), monitor platform-wide SMS usage, manage Platform Settings (Platform is open = No hides all rides/buttons and shows only the Maintenance Mode screen, Home Banner Message, Daily SMS Cap, Auto-Complete & Auto-Cleanup schedules), and toggle Feature Config switches (JumpIn Home Page iOS Theme, Broadcast SMS, & Need a Ride (Rider Requests)).
 Each group has completely isolated trips, members, blocks, and settings. Non-default groups automatically inherit the Platform Support Handle if no custom tip handle is set, and the header Guide link is shown only to the Platform Admin.
SMS Budget & Opt-Out Compliance: Every outgoing text checks the configurable dailySmsCap before sending. If Twilio returns error 21610 (STOP / opt-out), JumpIn automatically marks that contact opted out so they are excluded from future broadcasts. Users can reply START or UNSTOP to resume texts anytime.
